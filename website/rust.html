Rust

A safe API, Listener and Connection, over the raw FFI crate fipc-sys, for Rust 1.85 and later, with no other dependencies. Calls return Result<T, Error>; handles close when dropped; the borrow checker keeps the C API's rules on threads and zero-copy buffers. The -sys crate carries the native library for Windows x64, Linux x64 (glibc 2.34+) and macOS 14.4+ on Apple Silicon, and links it.

Server and client

two processes, one name

Start the two in either order, in two terminals: Connection::connect waits up to its timeout for a server to listen and accept. Each file is a program of its own (src/main.rs, or an example: cargo run --example server). A timeout is anything that converts into an Option<Duration>: None waits as long as it takes. The pair makes the exchange every example on this site makes, an RPC request with opcode 1 and the payload ping, answered in upper case: this client works with any language's server, and this server with any language's client.

server.rs
use fipc::Listener;

fn main() -> fipc::Result<()> {
    let mut listener = Listener::listen("my_channel", 1 << 20)?; // rings of 1 MiB each way
    let mut conn = listener.accept(None)?; // waits for a client
    let request = conn.rpc_receive(None)?;
    conn.rpc_respond(request.id, request.opcode, 0, &request.payload.to_ascii_uppercase(), None)?;
    Ok(())
}
client.rs
use fipc::Connection;
use std::time::Duration;

fn main() -> fipc::Result<()> {
    let mut conn = Connection::connect("my_channel", Duration::from_secs(5))?;
    conn.rpc_submit(1, b"ping", None)?; // opcode 1
    println!("{}", String::from_utf8_lossy(&conn.rpc_receive(None)?.payload)); // PING
    Ok(())
}

Plain messages

bytes of any size, no header

Without RPC, a connection carries plain messages: send takes a message of any size, and receive returns each one whole in a new Vec (or fills your buffer). This server echoes every message back until its client leaves, which ends its next receive with Error::Disconnected.

echo_server.rs
use fipc::{Error, Listener};

fn main() -> fipc::Result<()> {
    // rings of 1 MiB each way: a power of two, 1 KiB to 2 GiB
    let mut listener = Listener::listen("demo", 1 << 20)?;
    let mut conn = listener.accept(None)?; // waits for a client
    loop {
        match conn.receive(None) {
            Ok(message) => conn.send(&message, None)?, // echo, any size
            Err(Error::Disconnected) => break,
            Err(e) => return Err(e),
        }
    }
    println!("client gone");
    Ok(())
}
echo_client.rs
use fipc::Connection;
use std::time::Duration;

fn main() -> fipc::Result<()> {
    let mut conn = Connection::connect("demo", Duration::from_secs(5))?;
    for word in ["hello", "shared", "memory"] {
        conn.send(word.as_bytes(), None)?;
        println!("{}", String::from_utf8_lossy(&conn.receive(None)?));
    }
    Ok(())
}

Errors and timeouts

fipc::Error mirrors fipc_result_t

Every call that can fail returns fipc::Result<T>. Error is an enum: Timeout, Disconnected, Cancelled, TooLarge { len } (the room a receive needs; the message stays queued), Invalid, NoMemory or AddrInUse. It implements std::error::Error, displays the C name (FIPC_TIMEOUT: the timeout ran out) and converts into std::io::Error.

The timeout comes last: a Duration, NO_WAIT (doesn't wait), or None / FOREVER. Disconnected is final for that connection: drop it, then accept or connect a new one.

wait at most 100 ms
match conn.receive(Duration::from_millis(100)) {
    Ok(message) => handle(&message),
    Err(Error::Timeout) => {} // nothing yet
    Err(e) => return Err(e),  // Error::Disconnected: the peer is gone
}

Zero-copy

up to conn.max_piece() bytes

Write into a SendSlot of the ring and commit it; read a ReceiveSlot of the ring, which frees its room when dropped. Both deref to [u8]. A slot borrows its side of the connection, so the borrow checker keeps it from outliving its turn: nothing else is sent (or received) while it lives. Dropping a SendSlot without committing it sends nothing.

send in place
let mut slot = conn.send_acquire(5, None)?; // room in the ring
slot.copy_from_slice(b"hello");
slot.commit(5)?;
receive in place
let message = conn.receive_acquire(None)?; // read-only, in the ring
handle(&message);
drop(message); // frees its room

RPC

RpcMessage { id, kind, opcode, status, payload }

Requests carry your opcode; responses echo the request's id and add a status. Either side may submit. rpc_receive returns each payload in a new Vec; rpc_receive_into fills your buffer and returns an RpcHeader, with no allocation per message. Use a connection for RPC or for plain messages, not both. This server answers requests until its client leaves, and this client checks what came back; either makes the exchange above with the other half in any language.

rpc_server.rs
use fipc::{Error, Listener, RpcKind};

const UPPER: u32 = 1;

fn main() -> fipc::Result<()> {
    let mut listener = Listener::listen("my_channel", 1 << 20)?;
    let mut conn = listener.accept(None)?;
    loop {
        let req = match conn.rpc_receive(None) {
            Ok(req) => req,
            Err(Error::Disconnected) => return Ok(()),
            Err(e) => return Err(e),
        };
        if req.kind == RpcKind::Request && req.opcode == UPPER {
            conn.rpc_respond(req.id, req.opcode, 0, &req.payload.to_ascii_uppercase(), None)?;
        }
    }
}
rpc_client.rs
use fipc::{Connection, RpcKind};
use std::time::Duration;

const UPPER: u32 = 1;

fn main() -> fipc::Result<()> {
    let mut conn = Connection::connect("my_channel", Duration::from_secs(5))?;
    let id = conn.rpc_submit(UPPER, b"ping", None)?;
    let reply = conn.rpc_receive(None)?;
    assert!(reply.kind == RpcKind::Response && reply.id == id);
    println!("{} {}", reply.status, String::from_utf8_lossy(&reply.payload)); // 0 PING
    Ok(())
}

one protocol

Threads

Send + Sync · &mut self · Canceler

Listener, Connection and its halves are Send and Sync. Calls that send or receive take &mut self, which is the C API's rule: one thread at a time sends, one at a time receives. To do both at once on two threads, split() the connection into its Sender and Receiver (borrowed) or into_split() it (owned); it closes when the last half is dropped.

To stop a thread that waits, take a Canceler first and call cancel() from any thread: every call that waits, then or later, returns Error::Cancelled. Then join the thread and drop the handle. A canceler doesn't keep the connection open.

stop a reader thread
let canceler = conn.canceler();
let reader = std::thread::spawn(move || {
    // until Error::Cancelled (or Error::Disconnected)
    while let Ok(message) = conn.receive(None) {
        handle(&message);
    }
});
// ...
canceler.cancel(); // wakes the reader: Cancelled
reader.join().unwrap();

Games and frame loops

never block a frame

Poll the connection once a frame with NO_WAIT, or give its Receiver to a thread that forwards messages through a channel the frame loop drains. In Bevy, a Connection (or the channel's receiving end) fits in a Resource and is polled in a system. game_loop.rs runs against echo_server.rs.

game_loop.rs
use fipc::{Connection, Error, NO_WAIT};
use std::time::Duration;

fn main() -> fipc::Result<()> {
    let mut conn = Connection::connect("demo", Duration::from_secs(5))?;
    let mut echoes = 0;
    for frame in 0..60u32 {
        conn.send(&frame.to_le_bytes(), NO_WAIT)?; // Error::Timeout only if the ring is full
        loop {
            match conn.receive(NO_WAIT) {
                Ok(_echo) => echoes += 1,
                Err(Error::Timeout) => break, // nothing more this frame
                Err(e) => return Err(e),      // Error::Disconnected: the peer is gone
            }
        }
        std::thread::sleep(Duration::from_millis(16)); // the rest of the frame
    }
    println!("{echoes} echoes in 60 frames");
    Ok(())
}

// Sending on this thread, receiving on another: the halves of the connection

Install and ship

Rust 1.85+ · x86-64-v3 · ARM64 Linux · Apple Silicon

fipc-sys links the library dynamically (on Windows through raw-dylib: no import library) and copies it into Cargo's build folder, where cargo run and cargo test find it. It takes the library from the folder FASTIPC_LIB_DIR names, else its own copy. On docs.rs nothing links.

A program started on its own needs the library beside it: on Windows, fastipc.dll next to the .exe; on Linux, libfastipc.so next to the executable, linked with an rpath of $ORIGIN; on macOS, libfastipc.dylib next to the executable, linked with an rpath of @loader_path. After a build the file is in target/<profile>/build/fipc-sys-*/out/; a build script of a crate that depends on fipc-sys gets that folder as DEP_FASTIPC_LIB_DIR.

Cargo.toml
[dependencies]
fipc = "1.0"
.cargo/config.toml (Linux, macOS: ship it next to the binary)
[target.x86_64-unknown-linux-gnu]
rustflags = ["-C", "link-arg=-Wl,-rpath,$ORIGIN"]

[target.aarch64-unknown-linux-gnu]
rustflags = ["-C", "link-arg=-Wl,-rpath,$ORIGIN"]

[target.aarch64-apple-darwin]
rustflags = ["-C", "link-arg=-Wl,-rpath,@loader_path"]
