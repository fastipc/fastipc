fipc on LuaRocks · require("fipc")

Lua

One module over LuaJIT's FFI, for LuaJIT 2.1 (also OpenResty's, Neovim's and LÖVE's): fipc.listen and fipc.connect give listeners and connections with plain, zero-copy and RPC messages. Nothing is compiled. A call that fails returns nil and the error's name, as Lua's io functions do, so assert() turns it into an error. The rock carries the native library for Windows x64, Linux x64 (glibc 2.34+) and macOS 14.4+ on Apple Silicon.

Server and client

two processes, one name

Start the two in either order, in two terminals (luajit server.lua, luajit client.lua): fipc.connect waits up to its timeout, in milliseconds, for a server to listen and accept; a call without a timeout waits as long as it takes. A Lua state has one thread, and connect waits for the server's accept: in Lua, a client and its server run in different processes. The pair makes the exchange every example on this site makes, an RPC request with opcode 1 and the payload ping, answered in upper case: this client works with any language's server, and this server with any language's client.

server.lua
local fipc = require("fipc")

local listener = assert(fipc.listen("my_channel", 1024 * 1024)) -- rings of 1 MiB each way
local conn = assert(listener:accept()) -- waits for a client
local request = assert(conn:rpc_recv())
assert(conn:rpc_respond(request.id, request.opcode, 0, request.payload:upper()))
conn:close()
listener:close()
client.lua
local fipc = require("fipc")

local conn = assert(fipc.connect("my_channel", 5000)) -- waits up to 5 s for the server
assert(conn:rpc_submit(1, "ping")) -- opcode 1
print(assert(conn:rpc_recv()).payload) -- PING
conn:close()

Plain messages

bytes of any size, no header

Without RPC, a connection carries plain messages: send takes a message of any size, a Lua string (or a cdata pointer and its length), and recv returns each one whole as a Lua string. This server echoes every message back until its client leaves, which ends its next recv with "disconnected".

echo_server.lua
local fipc = require("fipc")

-- rings of 1 MiB each way: a power of two, 1 KiB to 2 GiB
local listener = assert(fipc.listen("demo", 1024 * 1024))
local conn = assert(listener:accept()) -- waits for a client
while true do
    local message, err = conn:recv()
    if message then
        assert(conn:send(message)) -- echo, any size
    elseif err == fipc.DISCONNECTED then
        break
    else
        error(err)
    end
end
print("client gone")
conn:close()
listener:close()
echo_client.lua
local fipc = require("fipc")

local conn = assert(fipc.connect("demo", 5000))
for _, word in ipairs({ "hello", "shared", "memory" }) do
    assert(conn:send(word))
    print(assert(conn:recv()))
end
conn:close()

Errors and timeouts

nil and the error's name

A call that succeeds returns its value, or true when it has none. A call that doesn't returns nil and the error's name: "timeout", "disconnected", "cancelled", "too_large", "invalid", "no_memory" or "addr_in_use", the C API's results (fipc.TIMEOUT and the others are the same strings; fipc.result_str(err) gives the C name). Wrap a call in assert() to raise instead. A misuse raises: a closed handle, an argument of the wrong type. The timeout comes last, in milliseconds: fipc.NO_WAIT (0) doesn't wait, nil or fipc.FOREVER waits as long as it takes. "disconnected" is final: close the connection, then accept or connect a new one.

wait at most 100 ms
local message, err = conn:recv(100) -- waits at most 100 ms
if message then
    handle(message)
elseif err ~= fipc.TIMEOUT then -- "timeout": nothing yet, try again later
    error(err) -- "disconnected": the peer is gone
end
a buffer of your own: "too_large" says how much room
local buf = ffi.new("uint8_t[?]", 4096)
local len, err, needed = conn:recv_into(buf, 4096)
if err == fipc.TOO_LARGE then -- the message stays queued: make room, then take it
    buf = ffi.new("uint8_t[?]", needed)
    len = assert(conn:recv_into(buf, needed))
end

Zero-copy

up to conn:max_piece() bytes

Write a message into the ring and commit it; read one in the ring and release it. send_acquire returns a uint8_t* into the ring, 16-byte aligned; send_commit publishes its first bytes (all, or fewer). recv_acquire returns a const uint8_t* and the length, valid until recv_release, the next receive or close: copy out what you keep. A message of several pieces is "too_large" for recv_acquire and stays queued for recv.

send in place
local slot = assert(conn:send_acquire(5)) -- room in the ring: a uint8_t*
ffi.copy(slot, "hello", 5)
assert(conn:send_commit(5))
receive in place
local data, len = assert(conn:recv_acquire()) -- a const uint8_t* into the ring
handle(data, len) -- read it in place
conn:recv_release() -- frees its room

RPC

{ id, kind, opcode, status, payload }

Requests carry your opcode; responses echo the request's id and add a status (an int32). Either side may submit. rpc_recv returns a table with the payload as a string; rpc_recv_into(buf, size) puts the payload in your buffer and returns the table with len in its place. A payload may be empty (nil). Ids are Lua numbers, from 1. Use a connection for RPC or for plain messages, not both. This server answers requests until its client leaves; either half makes the exchange above with the other half in any language.

rpc_server.lua
local fipc = require("fipc")

local UPPER = 1

local listener = assert(fipc.listen("my_channel", 1024 * 1024))
local conn = assert(listener:accept())
while true do
    local req, err = conn:rpc_recv()
    if not req then
        if err == fipc.DISCONNECTED then
            break
        end
        error(err)
    end
    if req.kind == fipc.RPC_REQUEST and req.opcode == UPPER then
        assert(conn:rpc_respond(req.id, req.opcode, 0, req.payload:upper()))
    end
end
conn:close()
listener:close()
rpc_client.lua
local fipc = require("fipc")

local UPPER = 1

local conn = assert(fipc.connect("my_channel", 5000))
local id = assert(conn:rpc_submit(UPPER, "ping"))
local reply = assert(conn:rpc_recv())
assert(reply.kind == fipc.RPC_RESPONSE and reply.id == id)
print(reply.status, reply.payload) -- 0	PING
conn:close()

Threads and coroutines

one Lua state, one thread

A Lua state runs one thread at a time, so the C API's rule (on a connection, one thread sends and one receives) holds by itself. A call that waits blocks the whole state, every coroutine in it: in a coroutine scheduler, poll with fipc.NO_WAIT and yield while nothing has arrived. In OpenResty a call that waits blocks the nginx worker, so poll and ngx.sleep between polls; in Neovim, poll from a vim.uv timer.

conn:cancel() makes every call of the connection that waits, then or later, return "cancelled". A listener or connection belongs to the Lua state that made it; another state (another thread: love.thread, Lanes) opens a connection of its own. close() ends a connection at once; one the program drops is closed when the garbage collector frees it.

yield until a message comes
-- In a coroutine scheduler: poll, and yield until a message (or an error) comes
local function receive(conn)
    while true do
        local message, err = conn:recv(fipc.NO_WAIT)
        if message or err ~= fipc.TIMEOUT then
            return message, err
        end
        coroutine.yield()
    end
end

Games and frame loops

never block a frame

Poll the connection once a frame with fipc.NO_WAIT: send what the frame produced, then take every message that has arrived until "timeout" says there is none. In LÖVE, do it in love.update; a game that embeds LuaJIT does it in its own update. A send with NO_WAIT returns "timeout" only when the ring is full.

game_loop.lua runs against echo_server.lua above, sleeping for the rest of each frame as an engine's loop would.

game_loop.lua
local ffi = require("ffi")
local fipc = require("fipc")

-- The rest of a frame (a game engine's loop does this for you)
local sleep
if ffi.os == "Windows" then
    ffi.cdef("void Sleep(uint32_t ms);")
    sleep = function(ms) ffi.C.Sleep(ms) end
else
    ffi.cdef("int usleep(uint32_t us);")
    sleep = function(ms) ffi.C.usleep(ms * 1000) end
end

local conn = assert(fipc.connect("demo", 5000))
local echoes = 0
for frame = 1, 60 do
    assert(conn:send(tostring(frame), fipc.NO_WAIT)) -- "timeout" only if the ring is full
    while true do
        local echo, err = conn:recv(fipc.NO_WAIT)
        if echo then
            echoes = echoes + 1
        elseif err == fipc.TIMEOUT then
            break -- nothing more this frame
        else
            error(err) -- "disconnected": the peer is gone
        end
    end
    sleep(16)
end
print(echoes .. " echoes in 60 frames")
conn:close()

Install and ship

LuaJIT 2.1 · x86-64-v3 · ARM64 Linux · Apple Silicon

The rock installs the module and the library for your platform; LuaRocks must be set up for LuaJIT (--lua-version 5.1, --lua-dir). PUC Lua (5.1 to 5.4) has no FFI and isn't supported. Without LuaRocks, ship fipc.lua with fastipc.dll, libfastipc.so or libfastipc.dylib beside it, in a folder on package.path: the GitHub release's fipc-lua-1.0.0.tar.gz holds the module and every platform's library.

The module looks for the library in the folder FASTIPC_LIB_DIR names, then (in a checkout of the repository) its zig-out build, then its own folder, then the rock's copy on package.cpath, then the system's search. fipc.library says which file it loaded; the library stays loaded until the process ends.

with LuaRocks, for LuaJIT
luarocks --lua-version 5.1 install fipc
luajit -e 'print(require("fipc").library)'
shipped next to your code

  fastipc.dll        (Windows; libfastipc.so on Linux, libfastipc.dylib on macOS)
