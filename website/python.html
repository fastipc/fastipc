Python

Two classes, Listener and Conn, over the C API through CFFI's ABI mode: the native library is loaded at run time, so there is nothing to compile. A call that doesn't return OK raises FipcError. The wheels carry the library for Windows x64, Linux x64 (glibc 2.34+) and macOS 14.4+ on Apple Silicon; one wheel per platform fits every Python 3.9+.

Server and client

two processes, one name

Start the two in either order, in two terminals: Conn.connect waits up to its timeout for a server to listen and accept. Both classes are context managers. The pair makes the exchange every example on this site makes, an RPC request with opcode 1 and the payload ping, answered in upper case: this client works with any language's server, and this server with any language's client (every pair of languages is tested).

server.py
from fipc import Listener

# rings of 1 MiB each way
with Listener("my_channel", 1 << 20) as listener:
    with listener.accept() as conn:  # waits for a client
        request = conn.rpc_recv()
        conn.rpc_respond(request.id, request.opcode,
                         data=request.payload.upper())
client.py
from fipc import Conn

with Conn.connect("my_channel", timeout_ms=5000) as conn:
    conn.rpc_submit(1, b"ping")     # opcode 1
    print(conn.rpc_recv().payload)  # b'PING'

IPC overhead

what it costs to hand work to other processes, measured

Worker processes speed a job up only if talking to them is cheap. Every task crosses between processes twice, and that communication overhead, not the work, sets the limit. With one dispatcher handing out tasks of time t to P workers:

S= 1ct+1+R/tP ≤tc
S
speedup: how many times faster the job finishes than in one process
P
worker processes
t
time one task takes to compute
R
round trip: send a task to a worker and get its result back
c
the dispatcher's own time per task, handing it out and taking its result

However many workers, the job runs at most t / c times as fast. Python's own channels cost 20 to 70 µs a round trip and 8 to 56 µs of the dispatcher's time a task: tasks of 20 µs gain nothing from a pool fed through multiprocessing.Queue. FastIPC's round trip, Python to Python, is about 2 µs, so tasks of tens of microseconds scale across the cores. Every point on the chart is measured.

Where the formula comes from. Amdahl's law: if a share s of the work must run in one place, P workers finish it at most 1 / (s + (1 − s) / P) times as fast. Handing tasks to worker processes creates such a share even when the work itself splits perfectly: only the dispatcher can send a task and take its result, so its c per task acts as the serial share c/t, and a worker waits a round trip R for every task, which stretches each task to t + R. However many workers there are, the job never runs more than t / c times as fast.

One dispatcher process gives each worker one task at a time and takes the results in turn; each task and result is 64 bytes. R is the round trip with one worker; c the dispatcher's time per task with 2 to 12 workers, the tasks doing no work. Each point is the median of 3 runs.

Plain messages

bytes of any size, no header

Without RPC, a connection carries plain messages: send takes bytes of any size, and recv returns each message whole. This server echoes every message back until its client leaves, which ends its next recv with DISCONNECTED.

echo_server.py
from fipc import Listener, FipcError, Result

# rings of 1 MiB each way: a power of two, 1 KiB to 2 GiB
with Listener("demo", 1 << 20) as listener:
    with listener.accept() as conn:
        try:
            while True:
                msg = conn.recv()     # bytes, any size
                conn.send(msg)        # echo it back
        except FipcError as e:
            if e.result != Result.DISCONNECTED:
                raise
            print("client gone")
echo_client.py
from fipc import Conn

with Conn.connect("demo", timeout_ms=5000) as conn:
    for word in (b"hello", b"shared", b"memory"):
        conn.send(word)
        print(conn.recv())

Errors and timeouts

FipcError.result is a Result

Every waiting call takes timeout_ms: NO_WAIT (0) doesn't wait, FOREVER (−1, the default) waits for ever. Any result other than OK raises FipcError, whose result says which: TIMEOUT, DISCONNECTED, CANCELLED, TOO_LARGE, INVALID, NO_MEMORY or ADDR_IN_USE.

DISCONNECTED is final for that connection: close it, then accept or connect a new one.

poll without blocking
from fipc import FipcError, Result

try:
    msg = conn.recv(timeout_ms=100)
except FipcError as e:
    if e.result == Result.TIMEOUT:
        msg = None            # nothing yet
    else:
        raise

Zero-copy

up to conn.max_piece() bytes

Write into a memoryview of the ring and commit; read a read-only memoryview of the ring and release it. A view stays valid until its release, the next receive, or close.

send in place
buf = conn.send_acquire(5)    # writable memoryview
buf[:] = b"hello"
conn.send_commit(5)
receive in place
view = conn.recv_acquire()    # read-only memoryview
handle(view)
conn.recv_release()           # frees its room

RPC

RpcMessage(id, kind, opcode, status, payload)

Requests carry your opcode; responses echo the request's id and add a status. Either side may submit. Use a connection for RPC or for plain messages, not both. This server answers requests until its client leaves, and this client checks what came back; either makes the exchange above with the other half in any language.

rpc_server.py
from fipc import (Listener, FipcError, Result,
                         RPC_REQUEST)

UPPER = 1

with Listener("my_channel", 1 << 20) as listener, \
        listener.accept() as conn:
    try:
        while True:
            req = conn.rpc_recv()
            if req.kind == RPC_REQUEST and req.opcode == UPPER:
                conn.rpc_respond(req.id, req.opcode, status=0,
                                 data=req.payload.upper())
    except FipcError as e:
        if e.result != Result.DISCONNECTED:
            raise
rpc_client.py
from fipc import Conn, RPC_RESPONSE

UPPER = 1

with Conn.connect("my_channel", timeout_ms=5000) as conn:
    req_id = conn.rpc_submit(UPPER, b"ping")
    reply = conn.rpc_recv()
    assert reply.kind == RPC_RESPONSE
    assert reply.id == req_id
    print(reply.status, reply.payload)   # 0 b'PING'

Threads

cancel, join, close

On a connection, one thread at a time sends and one thread at a time receives, and the two may run at once. cancel() works from any thread and makes every waiting call raise CANCELLED. close() needs the connection to itself, so stop a reader thread by cancelling, joining it, then closing.

stop a reader thread
import threading
from fipc import FipcError

def reader():
    try:
        while True:
            handle(conn.recv())
    except FipcError:
        pass                      # CANCELLED or DISCONNECTED

t = threading.Thread(target=reader)
t.start()
...
conn.cancel()
t.join()
conn.close()
