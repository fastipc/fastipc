io.github.fastipc:fipc on Maven Central · module io.github.fastipc

Java

Two classes, Listener and Connection, over the C API through the FFM API (java.lang.foreign), for Java 22 and later: no JNI, no dependencies. A call that doesn't succeed throws FipcException. Both classes are AutoCloseable and safe to close from any thread. The jar carries the native library for Windows x64, Linux x64 (glibc 2.34+) and macOS 14.4+ on Apple Silicon.

Server and client

two processes, one name

Start the two in either order, in two terminals: Connection.connect waits up to its timeout for a server to listen and accept. With the jar on the class path, the source launcher runs each file as it is: java --enable-native-access=ALL-UNNAMED -cp fipc-1.0.0.jar Server.java. The pair makes the exchange every example on this site makes, an RPC request with opcode 1 and the payload ping, answered in upper case: this client works with any language's server, and this server with any language's client.

Server.java
import io.github.fastipc.Connection;
import io.github.fastipc.Listener;
import io.github.fastipc.RpcMessage;

public class Server {
    public static void main(String[] args) {
        // rings of 1 MiB each way; accept() waits for a client
        try (Listener listener =
                 Listener.listen("my_channel", 1 << 20);
             Connection conn = listener.accept()) {
            RpcMessage request = conn.rpcReceive();
            String text = new String(request.payload());
            conn.rpcRespond(request.id(), request.opcode(), 0,
                            text.toUpperCase().getBytes());
        }
    }
}
Client.java
import io.github.fastipc.Connection;
import java.time.Duration;

public class Client {
    public static void main(String[] args) {
        try (Connection conn = Connection.connect("my_channel",
                 Duration.ofSeconds(5))) {
            conn.rpcSubmit(1, "ping".getBytes());  // opcode 1
            byte[] reply = conn.rpcReceive().payload();
            System.out.println(new String(reply));  // PING
        }
    }
}

Plain messages

bytes of any size, no header

Without RPC, a connection carries plain messages: send takes a message of any size, and receive returns each one whole in a new array (or fills your buffer). This server echoes every message back until its client leaves, which ends its next receive with DISCONNECTED.

EchoServer.java
import io.github.fastipc.*;

public class EchoServer {
    public static void main(String[] args) {
        // rings of 1 MiB each way: a power of two, 1 KiB to 2 GiB
        try (Listener listener = Listener.listen("demo", 1 << 20);
             Connection conn = listener.accept()) {
            while (true) {
                conn.send(conn.receive());   // echo, any size
            }
        } catch (FipcException e) {
            if (e.result() != Result.DISCONNECTED) throw e;
            System.out.println("client gone");
        }
    }
}
EchoClient.java
import io.github.fastipc.Connection;
import java.time.Duration;

public class EchoClient {
    public static void main(String[] args) {
        try (Connection conn =
                 Connection.connect("demo", Duration.ofSeconds(5))) {
            for (String word : new String[] {"hello", "shared", "memory"}) {
                conn.send(word.getBytes());
                System.out.println(new String(conn.receive()));
            }
        }
    }
}

Errors and timeouts

FipcException.result() is a Result

Every call that can wait has an overload without a timeout, which waits for ever, and one that takes a java.time.Duration: Fipc.NO_WAIT (Duration.ZERO) doesn't wait, Fipc.FOREVER waits for ever. A call that doesn't succeed throws FipcException, unchecked, whose result() says why: TIMEOUT, DISCONNECTED, CANCELLED, TOO_LARGE, INVALID, NO_MEMORY or ADDR_IN_USE.

DISCONNECTED is final for that connection: close it, then accept or connect a new one. A call on a closed listener or connection throws IllegalStateException.

poll without blocking
byte[] msg;
try {
    msg = conn.receive(Duration.ofMillis(100));
} catch (FipcException e) {
    if (e.result() != Result.TIMEOUT) throw e;
    msg = null;                    // nothing yet
}

Zero-copy

up to conn.maxPiece() bytes

Write into a MemorySegment of the ring and commit; read a read-only MemorySegment of the ring and release it. A segment is valid until its commit or release and confined to the thread that acquired it: touching it afterwards, or from another thread, throws instead of reaching memory that is no longer yours.

send in place
MemorySegment room = conn.sendAcquire(5);   // in the ring
room.copyFrom(MemorySegment.ofArray("hello".getBytes()));
conn.sendCommit(5);
receive in place
MemorySegment message = conn.receiveAcquire();  // read-only, in the ring
handle(message);
conn.receiveRelease();                          // frees its room

RPC

RpcMessage(id, kind, opcode, status, payload)

Requests carry your opcode; responses echo the request's id and add a status. Either side may submit. rpcReceive() returns each payload in a new array; rpcReceive(buffer) fills yours and returns an RpcHeader, with no allocation per message. Use a connection for RPC or for plain messages, not both. This server answers requests until its client leaves, and this client checks what came back; either makes the exchange above with the other half in any language.

RpcServer.java
import io.github.fastipc.*;

public class RpcServer {
    static final int UPPER = 1;

    public static void main(String[] args) {
        try (Listener listener = Listener.listen("my_channel", 1 << 20);
             Connection conn = listener.accept()) {
            while (true) {
                RpcMessage req = conn.rpcReceive();
                if (req.isRequest() && req.opcode() == UPPER) {
                    byte[] upper = new String(req.payload())
                        .toUpperCase().getBytes();
                    conn.rpcRespond(req.id(), req.opcode(), 0, upper);
                }
            }
        } catch (FipcException e) {
            if (e.result() != Result.DISCONNECTED) throw e;
        }
    }
}
RpcClient.java
import io.github.fastipc.*;
import java.time.Duration;

public class RpcClient {
    static final int UPPER = 1;

    public static void main(String[] args) {
        try (Connection conn =
                 Connection.connect("my_channel", Duration.ofSeconds(5))) {
            long id = conn.rpcSubmit(UPPER, "ping".getBytes());
            RpcMessage reply = conn.rpcReceive();
            assert reply.isResponse() && reply.id() == id;
            System.out.println(reply.status() + " "
                + new String(reply.payload()));   // 0 PING
        }
    }
}

Any language on the other end

one protocol

The Server and Client above work with a peer in any of the ten languages: every pair of languages is tested.

Threads and close

close, then join

On a connection, one thread at a time sends and one thread at a time receives, and the two may run at once. cancel() and close() may be called from any thread, at any time. close() cancels the connection, so a waiting call throws CANCELLED, and the native close runs once the calls in progress have returned: no call ever runs on a closed connection.

Waits are not interruptible: Thread.interrupt() doesn't wake a call; cancel() and close() do. A waiting call blocks its thread in native code, which pins a virtual thread, so use platform threads for calls that wait long. A listener or connection that is never closed is closed by a Cleaner once it is unreachable.

stop a reader thread
Thread reader = Thread.ofPlatform().start(() -> {
    try {
        while (true) {
            handle(new String(conn.receive()));
        }
    } catch (FipcException e) {
        // CANCELLED (closed) or DISCONNECTED
    }
});
...
conn.close();       // wakes the reader: CANCELLED
reader.join();

Install and native access

Java 22+ · FFM API

The binding calls restricted methods of the FFM API, so grant it native access, or the JVM prints a warning on the first call: --enable-native-access=ALL-UNNAMED with the jar on the class path, --enable-native-access=io.github.fastipc on the module path, or Enable-Native-Access: ALL-UNNAMED in an executable jar's manifest.

The jar's native library is extracted once per content into the user's cache (%LOCALAPPDATA%\fipc, ~/.cache/fipc, on macOS ~/Library/Caches/fipc) and checked before each load. The system property fastipc.library.path names another one; Fipc.libraryPath() says which was loaded.

build.gradle.kts
plugins {
    application
}

repositories {
    mavenCentral()
}

dependencies {
    implementation("io.github.fastipc:fipc:1.0.0")
}

application {
    mainClass = "Server"
    applicationDefaultJvmArgs =
        listOf("--enable-native-access=ALL-UNNAMED")
}

listener.accept([timeout])Sets the next client's connection up on the calling thread and returns its Connection. One client at a time: close it before the next accept. Fipc.NO_WAIT polls.

receive([timeout])Receives one message of any size as a new byte[].
