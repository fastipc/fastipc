C++

One header over the C API: fipc::listener and fipc::connection own their handles and close them when destroyed; every call returns a fipc::result<T>, so it builds with -fno-exceptions and without RTTI; timeouts are std::chrono durations. It wraps the 18 functions of fipc.h and adds no ABI of its own, so it works with the same fastipc.dll / libfastipc.so / libfastipc.dylib, and its processes talk to every other language's.

Server and client

two processes, one name

Run the server in one process, then the client in another; connect waits up to its timeout for a server to listen and accept. A result converts to true when it holds a value, and -> reaches it. The pair makes the exchange every example on this site makes, an RPC request with opcode 1 and the payload ping, answered in upper case: this client works with any language's server, and this server with any language's client (every pair of languages is tested).

server.cpp
#include <cctype>
#include <string>

#include <fipc.hpp>

int main()
{
    auto listener = fipc::listener::listen("my_channel", 1 << 20);  // rings of 1 MiB each way
    if (!listener)
        return 1;
    auto conn = listener->accept();  // waits for a client
    if (!conn)
        return 1;
    std::string payload;
    auto request = conn->rpc_receive(payload);
    if (!request)
        return 1;
    for (char& c : payload)
        c = static_cast<char>(std::toupper(static_cast<unsigned char>(c)));
    return conn->rpc_respond(request->id, request->opcode, 0, payload) ? 0 : 1;
}
client.cpp
#include <chrono>
#include <cstdio>
#include <string>

#include <fipc.hpp>

int main()
{
    auto conn = fipc::connection::connect("my_channel", std::chrono::seconds(5));
    if (!conn)
    {
        std::fprintf(stderr, "connect: %s\n", conn.error().name());
        return 1;
    }
    std::string reply;
    if (!conn->rpc_submit(1, "ping") || !conn->rpc_receive(reply))  // opcode 1
        return 1;
    std::printf("%s\n", reply.c_str());  // PING
    return 0;
}

Build

the Zig build system · no CMake

The recommended way is the Zig build system: no CMake or other build tool, and Zig 0.17.0 is a single download. It builds the library for your target and compiles your C++ with its bundled Clang. The dependency's artifact fastipc is the shared library; linking it puts fipc.h and fipc.hpp on the include path. The repository's examples/c-cpp is such a project, with these servers and clients in C and C++.

Any other C++20 compiler works too: take the headers and the library from the GitHub release's archive for your OS, or from zig build in a checkout (zig-out/include, zig-out/lib, zig-out/bin). On macOS, link with an rpath to the dylib's folder, and clear a browser-downloaded archive's quarantine flag (xattr -d com.apple.quarantine lib/libfastipc.dylib; see the C page). On Windows, define FASTIPC_SHARED and put fastipc.dll next to the program; with MSVC and /EHs-c-, also define _HAS_EXCEPTIONS=0, as its standard library requires.

build.zig
const fastipc = b.dependency("fipc", .{
    .target = target,
    .optimize = optimize,
}).artifact("fastipc");
exe.root_module.link_libcpp = true;
exe.root_module.addCSourceFile(.{
    .file = b.path("src/server.cpp"),
    .flags = &.{"-std=c++20"},
});
exe.root_module.addCMacro("FASTIPC_SHARED", "1"); // Windows
exe.root_module.linkLibrary(fastipc);
b.installArtifact(fastipc); // the library next to the programs
shell: other compilers
# Linux, from the release archive
g++ -std=c++20 -Iinclude server.cpp -Llib -lfastipc -o server
LD_LIBRARY_PATH=lib ./server

# macOS, from the release archive
clang++ -std=c++20 -Iinclude server.cpp -Llib -lfastipc -Wl,-rpath,@executable_path/lib -o server
./server

# Windows, MSVC (a developer prompt)
cl /std:c++20 /EHsc /DFASTIPC_SHARED /Iinclude server.cpp lib\fastipc.lib
copy bin\fastipc.dll .

Results and timeouts

fipc::result<T> · fipc::errc mirrors fipc_result_t

Every call that can fail returns a [[nodiscard]] fipc::result<T>, or fipc::status for calls that return nothing: like std::expected, it converts to true when it holds a value, *r and r-> reach it, and r.error() says why there is none. The error compares equal to its code: fipc::errc::timeout, disconnected, cancelled, too_large (error().len is the room the message needs; it stays queued), invalid, no_memory or addr_in_use; error().name() is the C name.

The timeout comes last: any std::chrono duration (rounded up to whole milliseconds), fipc::no_wait, or fipc::forever, the default of the calls that send, receive or accept. disconnected is final for that connection: destroy it, then accept or connect a new one.

wait at most 100 ms
std::string message;
auto got = conn.receive(message, std::chrono::milliseconds(100));
if (got)
    handle(message);
else if (got.error() != fipc::errc::timeout)
    return 1;  // fipc::errc::disconnected: the peer is gone

Plain messages

bytes of any size, no header

Without RPC, a connection carries plain messages of any size (at least one byte). send takes a std::string_view or a std::span<const std::byte>. receive fills a std::string or std::vector, resized to the message, whose capacity carries over to the next; receive_into fills a fixed buffer and returns the length.

send
if (!conn.send("hello"))  // std::string_view
    return 1;
std::vector<std::byte> data = encode(state);
if (!conn.send(data))  // std::span<const std::byte>
    return 1;
receive into a fixed buffer
char buf[256];
auto len = conn.receive_into(buf);
if (!len && len.error() == fipc::errc::too_large)
{
    // nothing was taken: make room, then again
    std::vector<char> big(len.error().len);
    len = conn.receive_into(big);
}

Zero-copy

up to conn.max_piece() bytes

Write into a fipc::send_slot of the ring and commit() it; a slot destroyed without its commit sends nothing. Read a fipc::receive_slot of the ring, which frees its room when destroyed. While a slot lives, its side of the connection makes no other call, and it must not outlive the connection; a slot whose turn a later acquire ended does nothing.

send in place
if (auto slot = conn.send_acquire(64))  // room in the ring
{
    int n = std::snprintf(reinterpret_cast<char*>(slot->data()), slot->size(), "tick %d", tick);
    if (!slot->commit(static_cast<std::size_t>(n)))  // publishes n bytes
        return 1;
}
receive in place
if (auto message = conn.receive_acquire())  // read-only, in the ring
    handle(message->bytes());  // std::span<const std::byte>
// destroyed here: its room is free again

RPC

fipc::rpc_header { id, kind, opcode, status, len }

Requests carry your opcode; responses echo the request's id and add a status. Either side may submit. rpc_submit returns the request's id; rpc_receive fills a resizable buffer with the payload and rpc_receive_into a fixed one, both returning the header. Use a connection for RPC or for plain messages, not both.

server: answer until the client leaves
std::string payload;
while (auto req = conn.rpc_receive(payload))
{
    if (req->kind != fipc::rpc_kind::request)
        continue;
    for (char& c : payload)
        c = static_cast<char>(std::toupper(static_cast<unsigned char>(c)));
    if (!conn.rpc_respond(req->id, req->opcode, 0, payload))
        break;
}
client: call and check
auto id = conn.rpc_submit(1, "ping");
std::string payload;
auto reply = conn.rpc_receive(payload);
if (id && reply && reply->kind == fipc::rpc_kind::response && reply->id == *id)
    std::printf("%d %s\n", reply->status, payload.c_str());  // 0 PING

Threads

one sender, one receiver · fipc::canceler

The C API's rule holds: on a connection, one thread at a time sends and one at a time receives, and the two may run at once; on a listener, one thread at a time accepts. max_piece() and cancel() work from any thread.

To stop a thread that waits, take a fipc::canceler first and call cancel() from any thread: every call that waits, then or later, returns fipc::errc::cancelled. Then join the thread and destroy the handle. A canceler doesn't keep its handle open: once the handle is closed, cancelling does nothing.

stop a reader thread
fipc::canceler canceler = conn.get_canceler();
std::thread reader([&conn] {
    std::string message;
    while (conn.receive(message))  // until cancelled or disconnected
        handle(message);
});
// ...
canceler.cancel();  // the reader's receive returns fipc::errc::cancelled
reader.join();
