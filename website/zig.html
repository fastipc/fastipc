Zig

The library is written in Zig, and its package exports the module fastipc: Listener and Conn over your own std.Io, with Zig error sets in place of result codes and std.Io.Timeout in place of milliseconds. It is the same implementation as the C API, compiled into your program, so there is no shared library to ship.

Install and build

Zig 0.17.0 · x86-64-v3 · ARM64 Linux · Apple Silicon

zig fetch --save adds the package to your build.zig.zon as fipc; for a checkout of your own, list it by path instead: .fipc = .{ .path = "../fastipc" }. Your build.zig then imports the dependency's module fastipc into each program that uses it.

The module is the library's own source (small enough to read), built with your target and optimize mode. It links libc and the system libraries it needs, which the package's build adds. It needs Zig 0.17.0 and runs where the library does: x86-64-v3 CPUs, Linux with glibc 2.34+ (x86-64 and ARM64), Windows 11 and Server 2022+, and macOS 14.4+ on Apple Silicon (platform support).

build.zig
const dep = b.dependency("fipc", .{
    .target = target,
    .optimize = optimize,
});
exe.root_module.addImport("fastipc", dep.module("fastipc"));
build.zig.zon, from a checkout
.dependencies = .{
    .fipc = .{ .path = "../fastipc" },
},

Server and client

two processes, one name

Each file is a program of its own, an executable in your build.zig; these two are the repository's examples/zig, a project that builds them. Start the two in either order: Conn.connect waits up to its timeout for a server to listen and accept. The client sends an RPC request with opcode 1 and the payload ping, and the server answers in upper case: the exchange every example on this site makes, so either program works with the other half in any language (every pair of languages is tested).

server.zig
const std = @import("std");
const fastipc = @import("fastipc");

pub fn main(init: std.process.Init) !void {
    // rings of 1 MiB each way
    const listener = try fastipc.Listener.listen(
        init.io,
        init.gpa,
        "my_channel",
        1 << 20,
    );
    defer listener.close();
    // waits for a client
    const conn = try listener.accept(.none);
    defer conn.close();

    var buf: [256]u8 = undefined;
    // .none: no timeout
    const req = try conn.rpcRecv(&buf, .none);
    const reply = std.ascii.upperString(&buf, req.payload);
    try conn.rpcRespond(req.id, req.opcode, 0, reply, .none);
}
client.zig
const std = @import("std");
const fastipc = @import("fastipc");

pub fn main(init: std.process.Init) !void {
    const five_s: std.Io.Timeout = .{ .duration = .{
        .raw = .fromSeconds(5),
        .clock = .awake,
    } };
    const conn = try fastipc.Conn.connect(
        init.io,
        init.gpa,
        "my_channel",
        five_s,
    );
    defer conn.close();
    _ = try conn.rpcSubmit(1, "ping", .none); // opcode 1
    var buf: [256]u8 = undefined;
    const response = try conn.rpcRecv(&buf, .none);
    std.debug.print("{s}\n", .{response.payload}); // PING
}

The rules

the C API's, in Zig terms
std.Io.Timeout

Timeouts

Always the last parameter. .none waits as long as it takes, a zero .duration doesn't wait, and a .deadline is a point in time. A call that runs out returns error.Timeout having changed nothing.

name · capacity

Names and rings

A name is 1 to 245 characters of [A-Za-z0-9_.-], not starting with . or -, local to the user (Linux, macOS) or the desktop session (Windows). The server picks the ring size: a power of two from 1 KiB to 2 GiB.

threads

One sender, one receiver

On a connection, one thread at a time sends and one receives, and the two may run at once. cancel works from any thread; no call may overlap close. To stop a waiting thread: cancel, join it, then close.

any size

Messages

A message holds at least one byte and arrives in order. send and recv take any size; a long message travels in pieces and is delivered whole or not at all.

error.TooLarge

Buffers too small

A recv or rpcRecv into a buffer that is too small takes nothing: the message stays queued. recvAlloc and rpcRecvAlloc take it at any size, into memory they allocate for exactly its length.

error.Disconnected

The peer's end

Final for that connection: sends return it at once, receives after every completed message, and ended() turns true. Close the connection, then accept or connect a new one.

Messages

bytes of any size, no header

send takes a message of any size and sends it in pieces of up to maxPiece() bytes when it is longer; its timeout bounds the wait for room for the first piece, and a started message completes unless a cancel or the peer's end stops it, which drops it whole. recv fills your buffer and returns the length; recvAlloc returns a new slice that you free. This server echoes every message back until its client leaves, which ends its next receive with error.Disconnected.

echo_server.zig
const std = @import("std");
const fastipc = @import("fastipc");

pub fn main(init: std.process.Init) !void {
    // rings of 1 MiB each way: a power of two, 1 KiB to 2 GiB
    const listener = try fastipc.Listener.listen(
        init.io,
        init.gpa,
        "demo",
        1 << 20,
    );
    defer listener.close();
    // waits for a client
    const conn = try listener.accept(.none);
    defer conn.close();
    while (true) {
        // a message of any size, in memory from gpa
        const message = conn.recvAlloc(
            init.gpa,
            .none,
        ) catch |err| switch (err) {
            error.Disconnected => break, // the client left
            else => return err,
        };
        defer init.gpa.free(message);
        try conn.send(message, .none); // echo it
    }
    std.debug.print("client gone\n", .{});
}

Errors and timeouts

error sets for fipc_result_t

Each error has the name of the C result code it stands for (the codes). listen and accept return fastipc.ListenError, connect returns fastipc.Error, and the data and RPC calls return fastipc.DataError; recvAlloc and rpcRecvAlloc add std.mem.Allocator.Error.

ErrorC codeReturned byMeaning
error.TimeoutFIPC_TIMEOUTevery call that waitsThe timeout ran out; with a zero duration, there was nothing to do without waiting.
error.DisconnectedFIPC_DISCONNECTEDthe data and RPC callsThe peer closed the connection or its process ended.
error.CancelledFIPC_CANCELLEDevery call that waitsThe handle's cancel was called, and the call would have had to wait. A data call that your Io cancels returns it too.
error.TooLargeFIPC_TOO_LARGErecv, rpcRecv, acquire, recvAcquireThe message (an RPC message's payload) doesn't fit the buffer, or one piece for zero-copy. A message being received stays queued, for recvAlloc or rpcRecvAlloc to take at any size.
error.InvalidFIPC_INVALIDany callA bad argument, a call out of order (an accept while the last client's connection is open), a peer of another version or user, corrupt ring content, a message that isn't an RPC message received by rpcRecv (dropped).
error.NoMemoryFIPC_NO_MEMORYlisten, accept, connectMemory or another OS resource ran out while setting a connection up.
error.AddrInUseFIPC_ADDR_IN_USElistenAnother listener holds the name.

} else |err| switch (err) {
    error.Timeout => {}, // nothing yet
    else => return err, // error.Disconnected: the peer is gone
}

The data and RPC calls (send, recv, recvAlloc, acquire, recvAcquire, rpcSubmit, rpcRespond, rpcRecv, rpcRecvAlloc) wait in whole milliseconds and round a timeout up to the next one.

Zero-copy

messages of one piece: up to conn.maxPiece() bytes

acquire returns room in the ring as a []u8; write the message there and commit the bytes you wrote, at least one. recvAcquire returns the next message where it lies, as a []const u8 that stays valid until release, the next receive or close. maxPiece() is the ring's capacity less 64 bytes. A longer message goes through send, and recvAcquire returns error.TooLarge for a message of several pieces, which stays queued for recv.

send in place
const out = try conn.acquire(64, .none); // room in the ring
const text = try std.mem.print(out, "tick {d}", .{tick});
try conn.commit(text.len); // publishes text.len bytes
receive in place
// the next message, read-only, in the ring
const message = try conn.recvAcquire(.none);
handle(message);
conn.release(); // frees its room

Threads and your Io

std.Io.Threaded · cancel

accept and connect set a connection up on the thread that calls them, so a client and its server run on different threads or processes. Then every connection runs a task on the Io you pass, which watches the peer. That Io must run concurrent tasks, as std.Io.Threaded does; the Io that std.process.Init hands to main is one. Don't cancel the library's tasks through it.

Listener and Conn are handles, copied by value. To stop a thread that waits, call cancel() from any thread: every call of that handle that would wait, then or later, returns error.Cancelled, and calls that needn't wait still work. Then join the thread and close. The waits of accept and connect are the OS's, not your Io's: cancel() ends an accept, a timeout bounds a connect. When your Io cancels a task that waits in a data call, the call returns error.Cancelled and the cancelation stays pending for the task's next cancelation point.

stop a reader thread
const Reader = struct {
    fn run(c: fastipc.Conn) void {
        var buf: [4096]u8 = undefined;
        // until error.Cancelled (or error.Disconnected)
        while (c.recv(&buf, .none)) |len| {
            handle(buf[0..len]);
        } else |_| {}
    }
};
const reader = try std.Thread.spawn(.{}, Reader.run, .{conn});
// ...
conn.cancel(); // wakes the reader: error.Cancelled
reader.join();
conn.close();

RPC

RpcMessage { id, kind, opcode, status, payload }

Requests carry your opcode; responses echo the request's id and add a status. Either side may submit. rpcSubmit returns the request's id. rpcRecv fills your buffer and returns an RpcMessage whose payload is the part it filled, with no allocation per message; rpcRecvAlloc takes a payload of any size into memory from your allocator, which you free. A message that isn't an RPC message is dropped, with error.Invalid. Use a connection for RPC or for plain messages, not both. This server answers requests until its client leaves, and this client checks what came back; either makes the exchange above with the other half in any language.

rpc_server.zig
const std = @import("std");
const fastipc = @import("fastipc");

const upper: u32 = 1; // the opcode

pub fn main(init: std.process.Init) !void {
    const listener = try fastipc.Listener.listen(
        init.io,
        init.gpa,
        "my_channel",
        1 << 20,
    );
    defer listener.close();
    const conn = try listener.accept(.none);
    defer conn.close();
    while (true) {
        // a payload of any size, in memory from gpa
        const req = conn.rpcRecvAlloc(
            init.gpa,
            .none,
        ) catch |err| switch (err) {
            error.Disconnected => return, // the client left
            else => return err,
        };
        defer init.gpa.free(req.payload);
        // requests with this opcode only
        if (req.kind != .request or req.opcode != upper)
            continue;
        for (req.payload) |*c| c.* = std.ascii.toUpper(c.*);
        try conn.rpcRespond(
            req.id,
            req.opcode,
            0, // the status
            req.payload,
            .none,
        );
    }
}
rpc_client.zig
const std = @import("std");
const fastipc = @import("fastipc");

const upper: u32 = 1; // the opcode

pub fn main(init: std.process.Init) !void {
    const five_s: std.Io.Timeout = .{ .duration = .{
        .raw = .fromSeconds(5),
        .clock = .awake,
    } };
    const conn = try fastipc.Conn.connect(
        init.io,
        init.gpa,
        "my_channel",
        five_s,
    );
    defer conn.close();
    const id = try conn.rpcSubmit(upper, "ping", .none);
    var buf: [256]u8 = undefined;
    const reply = try conn.rpcRecv(&buf, five_s);
    std.debug.assert(reply.kind == .response);
    std.debug.assert(reply.id == id);
    std.debug.print("{d} {s}\n", .{
        reply.status,
        reply.payload,
    }); // 0 PING
}

CallWhat it does
Listener.listen(io, gpa, name, capacity)Claims the name and listens on it with rings of capacity bytes. Doesn't wait. error.AddrInUse if another listener holds the name.
listener.accept(timeout)Waits for a client, sets its connection up on the calling thread and returns its Conn. One client at a time: close it before the next accept. A zero timeout polls.
listener.cancel()Every accept that waits, now or later, returns error.Cancelled, dropping a client whose setup began. Any thread.
listener.close()Stops listening and frees the listener; the connections it accepted stay open.
Conn.connect(io, gpa, name, timeout)Connects to the server listening on the name, waiting up to the timeout for it to listen and accept.
conn.send(message, timeout)Sends one message of any size, in pieces if needed.
conn.recv(buf, timeout)Receives the next message into buf and returns its length; error.TooLarge if it doesn't fit (it stays queued).
conn.recvAlloc(gpa, timeout)Receives the next message into memory from gpa, which you free.
conn.rpcSubmit(opcode, payload, timeout)Sends a request and returns its id: the connection's next, never 0.
conn.rpcRespond(id, opcode, status, payload, timeout)Sends the response to request id.
conn.rpcRecv(buf, timeout)Receives the next request or response, its payload into buf, and returns it as an RpcMessage; error.TooLarge if the payload doesn't fit (it stays queued), error.Invalid for a message that isn't RPC (dropped).
conn.rpcRecvAlloc(gpa, timeout)Receives the next request or response, its payload into memory from gpa, which you free.
conn.acquire(len, timeout) · conn.commit(len)Zero-copy send: room for len bytes in the ring · sends the first len bytes written there as one message.
conn.recvAcquire(timeout) · conn.release()Zero-copy receive: the next message in place · frees its room.
conn.maxPiece()The longest message the zero-copy calls take: the capacity less 64 bytes.
conn.cancel()Every call of the connection that would wait, now or later, returns error.Cancelled. Any thread.
conn.ended()Whether the peer ended the session; its calls report error.Disconnected once nothing is left to receive.
conn.close()Ends the connection (the peer's calls report error.Disconnected), unmaps its rings and frees it. No other thread may be inside a call on it.
