github.com/fastipc/fastipc/bindings/go · package fipc

Go

One package, fipc, for Go 1.27 and later: fipc.Listen and fipc.Connect give a *Listener and a *Conn with plain, zero-copy and RPC messages. Every method is safe from any goroutine, as with a net.Conn; failures are errors to test with errors.Is, and timeouts are time.Durations. No cgo: the package loads the native library at run time through purego, so CGO_ENABLED=0 builds and cross-compiling work and no C compiler is needed. The module carries the native library for Windows x64, Linux x64 and ARM64 (glibc 2.34+) and macOS 14.4+ on Apple Silicon.

Server and client

two processes, one name

Start the two in either order, in two terminals (go run server.go, go run client.go; in a checkout of the repository, go run ./examples/server and go run ./examples/client in bindings/go): fipc.Connect waits up to its timeout for a server to listen and accept; fipc.Forever waits as long as it takes. The pair makes the exchange every example on this site makes, an RPC request with opcode 1 and the payload ping, answered in upper case: this client works with any language's server, and this server with any language's client.

server.go
package main

import (
	"bytes"
	"log"

	"github.com/fastipc/fastipc/bindings/go/fipc"
)

func main() {
	listener, err := fipc.Listen("my_channel", 1<<20) // rings of 1 MiB each way
	if err != nil {
		log.Fatal(err)
	}
	defer listener.Close()
	conn, err := listener.Accept(fipc.Forever) // waits for a client
	if err != nil {
		log.Fatal(err)
	}
	defer conn.Close()
	request, err := conn.RPCReceive(fipc.Forever)
	if err != nil {
		log.Fatal(err)
	}
	err = conn.RPCRespond(request.ID, request.Opcode, 0, bytes.ToUpper(request.Payload), fipc.Forever)
	if err != nil {
		log.Fatal(err)
	}
}
client.go
package main

import (
	"fmt"
	"log"
	"time"

	"github.com/fastipc/fastipc/bindings/go/fipc"
)

func main() {
	conn, err := fipc.Connect("my_channel", 5*time.Second) // waits up to 5 s for the server
	if err != nil {
		log.Fatal(err)
	}
	defer conn.Close()
	if _, err := conn.RPCSubmit(1, []byte("ping"), fipc.Forever); err != nil { // opcode 1
		log.Fatal(err)
	}
	reply, err := conn.RPCReceive(fipc.Forever)
	if err != nil {
		log.Fatal(err)
	}
	fmt.Println(string(reply.Payload)) // PING
}

Plain messages

bytes of any size, no header

Without RPC, a connection carries plain messages: Send takes a []byte of any size (at least 1 byte), and Receive returns each message whole, in a new slice; ReceiveInto fills a buffer of yours and returns the length, without allocating. A message longer than the ring travels in pieces and arrives whole. This server echoes every message back until its client leaves, which ends its next Receive with fipc.ErrDisconnected.

echo_server.go
package main

import (
	"errors"
	"fmt"
	"log"

	"github.com/fastipc/fastipc/bindings/go/fipc"
)

func main() {
	// rings of 1 MiB each way: a power of two, 1 KiB to 2 GiB
	listener, err := fipc.Listen("demo", 1<<20)
	if err != nil {
		log.Fatal(err)
	}
	defer listener.Close()
	conn, err := listener.Accept(fipc.Forever) // waits for a client
	if err != nil {
		log.Fatal(err)
	}
	defer conn.Close()
	for {
		msg, err := conn.Receive(fipc.Forever)
		if errors.Is(err, fipc.ErrDisconnected) {
			break
		} else if err != nil {
			log.Fatal(err)
		}
		if err := conn.Send(msg, fipc.Forever); err != nil { // echo, any size
			log.Fatal(err)
		}
	}
	fmt.Println("client gone")
}
echo_client.go
package main

import (
	"fmt"
	"log"
	"time"

	"github.com/fastipc/fastipc/bindings/go/fipc"
)

func main() {
	conn, err := fipc.Connect("demo", 5*time.Second)
	if err != nil {
		log.Fatal(err)
	}
	defer conn.Close()
	for _, word := range []string{"hello", "shared", "memory"} {
		if err := conn.Send([]byte(word), fipc.Forever); err != nil {
			log.Fatal(err)
		}
		echo, err := conn.Receive(fipc.Forever)
		if err != nil {
			log.Fatal(err)
		}
		fmt.Println(string(echo))
	}
}

Errors and timeouts

*fipc.Error mirrors fipc_result_t

A call the library refuses returns one of fipc.ErrTimeout, ErrDisconnected, ErrCancelled, ErrTooLarge, ErrInvalid, ErrNoMemory or ErrAddrInUse, the C API's results, as *fipc.Error values: test them with errors.Is. Their messages are the C names (FIPC_TIMEOUT: the timeout ran out), and ErrTimeout's Timeout() is true, as for the deadlines of packages os and net. A call on a closed handle returns fipc.ErrClosed; one that can't load the library, an error that wraps fipc.ErrNoLibrary and says where it looked. The timeout comes last, a time.Duration counted in whole milliseconds, rounded up: fipc.NoWait (0) doesn't wait, fipc.Forever (or any negative duration) waits as long as it takes. ErrDisconnected is final: close the connection, then accept or connect a new one.

wait at most 100 ms
msg, err := conn.Receive(100 * time.Millisecond)
switch {
case err == nil:
	handle(msg)
case errors.Is(err, fipc.ErrTimeout): // nothing yet
default:
	return err // fipc.ErrDisconnected: the peer is gone
}
a buffer of your own: ErrTooLarge says how much room
n, err := conn.ReceiveInto(buf, fipc.Forever)
var e *fipc.Error
if errors.As(err, &e) && e.Len() > 0 { // ErrTooLarge: make room, then again
	buf = make([]byte, e.Len())
	n, err = conn.ReceiveInto(buf, fipc.Forever)
}

Zero-copy

up to conn.MaxPiece() bytes

Write a message into the ring and commit it; read one in the ring and release it. SendAcquire(n) returns a slice over room in the ring, valid until SendCommit, the next send or Close; ReceiveAcquire returns a read-only slice over the message, valid until ReceiveRelease, the next receive or Close. These slices point into shared memory: using one after that is undefined and may crash the program, so copy what must outlive it, and keep the connection reachable while you use one. A message of several pieces is ErrTooLarge for ReceiveAcquire and stays queued for Receive. In Go, zero-copy is slower than copying for short messages (below): it takes two calls into the library per message on each side where a copy takes one, and through purego a call costs more than copying a short message. It pays off for long messages you would otherwise copy again.

send in place
buf, err := conn.SendAcquire(5, fipc.Forever) // room in the ring
if err != nil {
	return err
}
copy(buf, "hello")
return conn.SendCommit(5) // sent; buf is no longer valid
receive in place
msg, err := conn.ReceiveAcquire(fipc.Forever) // the message in the ring, read-only
if err != nil {
	return err
}
handle(msg)           // read it in place
conn.ReceiveRelease() // frees its room; msg is no longer valid

RPC

RPCMessage{ID, Kind, Opcode, Status, Payload}

Requests carry your opcode; responses echo the request's id and add a status (an int32). Either side may submit. RPCReceive returns an RPCMessage with the payload in a new slice; RPCReceiveInto(buf) puts the payload in your buffer and returns an RPCHeader with its length, with no allocation per message. A payload may be empty (nil). Several requests may be in flight; correlate the responses by id. Use a connection for RPC or for plain messages, not both. This server answers requests until its client leaves, and this client checks what came back; either makes the exchange above with the other half in any language.

rpc_server.go
package main

import (
	"bytes"
	"errors"
	"log"

	"github.com/fastipc/fastipc/bindings/go/fipc"
)

const upper = 1

func main() {
	listener, err := fipc.Listen("my_channel", 1<<20)
	if err != nil {
		log.Fatal(err)
	}
	defer listener.Close()
	conn, err := listener.Accept(fipc.Forever)
	if err != nil {
		log.Fatal(err)
	}
	defer conn.Close()
	for {
		req, err := conn.RPCReceive(fipc.Forever)
		if errors.Is(err, fipc.ErrDisconnected) {
			return
		} else if err != nil {
			log.Fatal(err)
		}
		if req.Kind == fipc.RPCRequest && req.Opcode == upper {
			if err := conn.RPCRespond(req.ID, req.Opcode, 0, bytes.ToUpper(req.Payload), fipc.Forever); err != nil {
				log.Fatal(err)
			}
		}
	}
}
rpc_client.go
package main

import (
	"fmt"
	"log"
	"time"

	"github.com/fastipc/fastipc/bindings/go/fipc"
)

const upper = 1

func main() {
	conn, err := fipc.Connect("my_channel", 5*time.Second)
	if err != nil {
		log.Fatal(err)
	}
	defer conn.Close()
	id, err := conn.RPCSubmit(upper, []byte("ping"), fipc.Forever)
	if err != nil {
		log.Fatal(err)
	}
	reply, err := conn.RPCReceive(fipc.Forever)
	if err != nil {
		log.Fatal(err)
	}
	if reply.Kind != fipc.RPCResponse || reply.ID != id {
		log.Fatalf("not the response to request %d: %+v", id, reply)
	}
	fmt.Println(reply.Status, string(reply.Payload)) // 0 PING
}

Any language on the other end

one protocol

The server.go and client.go above work with a peer in any of the ten languages: every pair of languages is tested. A Go service can serve a Python or JavaScript front end, or a game's editor in C#, without a socket.

Goroutines, cancel and close

net.Conn semantics · context.AfterFunc

Every method of a Listener or Conn is safe to call from any goroutine. Each direction of a connection has a mutex of its own: concurrent sends run one at a time, each message whole, and so do concurrent receives, while one goroutine sends and another receives at once. A client and its server in one process run on different goroutines, since Connect waits for the server's Accept. A call that waits holds its goroutine's thread in the library, as a cgo call does; the scheduler runs the other goroutines on other threads.

To stop a goroutine that waits, call conn.Cancel() (or listener.Cancel()) from another one: every call that waits, then or later, returns fipc.ErrCancelled. With a context, context.AfterFunc(ctx, conn.Cancel) cancels the connection when the context is done.

conn.Close() ends the connection: the peer gets ErrDisconnected once it has received what this side sent. It may run while other goroutines are inside calls: it cancels the connection, waits for them to return, then closes; later calls, and a second Close, return ErrClosed. listener.Close() stops listening and leaves the connections it accepted open. A handle that becomes unreachable without Close is closed by the garbage collector, some time later. There is no heartbeat and no timeout: a paused or hung peer is not reported, a crashed or killed one as soon as its process has ended.

stop a reader goroutine
done := make(chan struct{})
go func() {
	defer close(done)
	// until fipc.ErrCancelled (or fipc.ErrDisconnected)
	for {
		msg, err := conn.Receive(fipc.Forever)
		if err != nil {
			return
		}
		handle(msg)
	}
}()
// ...
conn.Cancel() // wakes the reader: ErrCancelled
<-done        // then close the connection, or go on with calls that needn't wait
cancel with a context
stop := context.AfterFunc(ctx, conn.Cancel) // cancels the connection when ctx is done
defer stop()

Games and frame loops

never block a frame

Poll the connection once a frame with fipc.NoWait, or give the receiving to a goroutine that forwards each message through a channel the frame loop drains. In an Ebitengine game, poll in Update, which runs 60 times a second by default. game_loop.go runs against echo_server.go.

game_loop.go
package main

import (
	"encoding/binary"
	"errors"
	"fmt"
	"log"
	"time"

	"github.com/fastipc/fastipc/bindings/go/fipc"
)

func main() {
	conn, err := fipc.Connect("demo", 5*time.Second)
	if err != nil {
		log.Fatal(err)
	}
	defer conn.Close()
	echoes := 0
	buf := make([]byte, 64)
	for frame := range uint32(60) {
		update := binary.LittleEndian.AppendUint32(nil, frame)
		if err := conn.Send(update, fipc.NoWait); err != nil { // ErrTimeout only if the ring is full
			log.Fatal(err)
		}
		for {
			_, err := conn.ReceiveInto(buf, fipc.NoWait)
			if errors.Is(err, fipc.ErrTimeout) {
				break // nothing more this frame
			} else if err != nil {
				log.Fatal(err) // ErrDisconnected: the peer is gone
			}
			echoes++
		}
		time.Sleep(16 * time.Millisecond) // the rest of the frame
	}
	fmt.Printf("%d echoes in 60 frames\n", echoes)
}
a reader goroutine and a channel
messages := make(chan []byte, 64)
go func() {
	defer close(messages)
	for {
		msg, err := conn.Receive(fipc.Forever)
		if err != nil {
			return // ErrDisconnected, or ErrCancelled once the game closes the connection
		}
		messages <- msg
	}
}()
// Each frame: whatever has arrived, without waiting
for len(messages) > 0 {
	handle(<-messages)
}

Install and ship

Go 1.27+ · no cgo · x86-64-v3 · ARM64 Linux · Apple Silicon

No cgo. The module's one dependency is github.com/ebitengine/purego, which loads a shared library and calls its C functions from pure Go on Linux, macOS and Windows. Through it the package works with CGO_ENABLED=0: no C compiler on your machine or your build server, cross-compiling as for any pure Go program, and builds as fast as Go's. A program built with cgo works too.

Finding the library. The package loads fastipc.dll, libfastipc.so or libfastipc.dylib on the first Listen or Connect, looking in the folder FASTIPC_LIB_DIR names (when it is set, nowhere else); then next to the running executable; then in the copy the module carries, fipc/native/<platform>/, found from the package's source path, which serves go run, go test and programs built on your machine; then, in a checkout of the repository, its zig-out build; last, the system's search. fipc.LibraryPath() says which file it loaded; the library is never unloaded.

Shipping a program. Put the library next to the executable: the package loads it by its path, so no rpath and no install step are needed. Take it from the module's copy or from the GitHub release's archives; or keep it elsewhere and set FASTIPC_LIB_DIR. A program built with -trimpath, or run on another machine, doesn't find the module's copy.

add the module, build without cgo
go get github.com/fastipc/fastipc/bindings/go/fipc@latest
CGO_ENABLED=0 go build -o server .
ship it next to its library (here: for Linux on ARM64)
GOOS=linux GOARCH=arm64 go build -o dist/server .
cp "$(go env GOMODCACHE)"/github.com/fastipc/fastipc/bindings/go@v1.0.0/fipc/native/linux-arm64/libfastipc.so dist/
or point it at a folder
FASTIPC_LIB_DIR=/opt/myapp/lib ./server
