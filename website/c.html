Build and link

the Zig build system · no CMake

The recommended way to build C (and C++) against FastIPC is the Zig build system: no CMake or other build tool, and Zig 0.17.0 is a single download (a program written in Zig imports the Zig module instead). It builds the library for your target and compiles your C with its bundled Clang. After zig fetch --save git+https://github.com/fastipc/fastipc, your build.zig links the dependency's artifact fastipc, the shared library, which also puts fipc.h and fipc.hpp on the include path. The repository's examples/c-cpp is such a project, with the servers and clients of this page and the C++ page.

Any other compiler works too. Take the headers and the library from the GitHub release: an archive per OS with include/, and lib/libfastipc.so (Linux x64 or arm64), lib/libfastipc.dylib (macOS 14.4+ on Apple Silicon) or bin/fastipc.dll with its import library lib/fastipc.lib (Windows x64). Or build them in a checkout with zig build -Doptimize=ReleaseFast: zig-out/include, zig-out/lib and, on Windows, zig-out/bin. On Linux, the program finds libfastipc.so through an rpath, LD_LIBRARY_PATH or a system library directory. On macOS, the dylib's install name is @rpath/libfastipc.dylib, so link the program with an rpath to its folder; the dylib is ad hoc signed, not notarized, so after a browser download clear the archive's quarantine flag with xattr -d com.apple.quarantine lib/libfastipc.dylib (an app with the hardened runtime and library validation signs the dylib it embeds with its own identity). On Windows, define FASTIPC_SHARED so the header declares the functions dllimport, and put fastipc.dll next to the program or on PATH. Every build targets x86-64-v3 (on macOS, Apple M1 and macOS 14.4).

build.zig
const fastipc = b.dependency("fipc", .{
    .target = target,
    .optimize = optimize,
}).artifact("fastipc");
exe.root_module.addCSourceFile(.{
    .file = b.path("src/server.c"),
    .flags = &.{"-std=c11"},
});
exe.root_module.addCMacro("FASTIPC_SHARED", "1"); // Windows
exe.root_module.linkLibrary(fastipc);
b.installArtifact(fastipc); // the library next to the programs
shell: other compilers
# Linux, from the release archive
cc server.c -Iinclude -Llib -lfastipc -o server
LD_LIBRARY_PATH=lib ./server   # then ./client in another terminal

# macOS, from the release archive
xattr -d com.apple.quarantine lib/libfastipc.dylib   # if a browser downloaded it
cc server.c -Iinclude -Llib -lfastipc -Wl,-rpath,@executable_path/lib -o server
./server

# Windows, MSVC (a developer prompt)
cl /DFASTIPC_SHARED /Iinclude server.c lib\fastipc.lib
copy bin\fastipc.dll .

Server and client

two processes, one name

Run the server in one process, then the client in another; fipc_connect waits up to its timeout for a server to listen and accept. The pair makes the exchange every example on this site makes, an RPC request with opcode 1 and the payload ping, answered in upper case: this client works with any language's server, and this server with any language's client (every pair of languages is tested).

server.c
#include <ctype.h>
#include <fipc.h>

int main(void)
{
    fipc_listener_t* listener;
    if (fipc_listen("my_channel", 1 << 20, &listener) != FIPC_OK) /* rings of 1 MiB each way */
        return 1;
    fipc_conn_t* conn;
    if (fipc_accept(listener, &conn, FIPC_FOREVER) == FIPC_OK) /* waits for a client */
    {
        char buf[256];
        fipc_rpc_msg_t request;
        if (fipc_rpc_recv(conn, buf, sizeof buf, &request, FIPC_FOREVER) == FIPC_OK)
        {
            for (size_t i = 0; i < request.len; i++)
                buf[i] = (char) toupper((unsigned char) buf[i]);
            fipc_rpc_respond(conn, request.id, request.opcode, 0, buf, request.len, FIPC_FOREVER);
        }
        fipc_close(conn);
    }
    fipc_listener_close(listener);
    return 0;
}
client.c
#include <fipc.h>
#include <stdio.h>

int main(void)
{
    fipc_conn_t* conn;
    fipc_result_t result = fipc_connect("my_channel", &conn, 5000);
    if (result != FIPC_OK)
    {
        fprintf(stderr, "connect: %s\n", fipc_result_str(result));
        return 1;
    }
    uint64_t id;
    char buf[256];
    fipc_rpc_msg_t response;
    if (fipc_rpc_submit(conn, 1, "ping", 4, &id, FIPC_FOREVER) == FIPC_OK /* opcode 1 */
        && fipc_rpc_recv(conn, buf, sizeof buf, &response, FIPC_FOREVER) == FIPC_OK)
        printf("%.*s\n", (int) response.len, buf); /* PING */
    fipc_close(conn);
    return 0;
}

The rules

the header's conventions
timeout_ms

Timeouts

Always the last parameter, in milliseconds. FIPC_NO_WAIT (0) doesn't wait; FIPC_FOREVER (−1) waits for ever. A call that runs out returns FIPC_TIMEOUT having changed nothing.

name · capacity

Names and rings

A name is 1 to 245 characters of [A-Za-z0-9_.-], not starting with . or -, local to the user (Linux, macOS) or the desktop session (Windows). The server picks the ring size: a power of two from 1 KiB to 2 GiB.

threads

One sender, one receiver

On a connection, one thread at a time sends and one receives, and the two may run at once. Cancels work from any thread. To stop a waiting thread: cancel, join it, then close.

any size

Messages

A message holds at least one byte and arrives in order. The copying calls take any size; a long message travels in pieces and is delivered whole or not at all.

FIPC_TOO_LARGE

Buffers too small

A receive into a buffer that is too small takes nothing and reports the length, so allocate that much and call again. Pass a zero-length buffer to ask for the length only.

FIPC_DISCONNECTED

The peer's end

Final for that connection: sends return it at once, receives after every completed message. Close the connection, then accept or connect a new one.

Zero-copy

messages of one piece: up to fipc_max_piece(conn) bytes

Reserve room in the ring, write the message there, publish it. On the other side, read it where it lies and release it. Pointers are 16-byte aligned. fipc_max_piece is the ring's capacity less 64 bytes; anything longer goes through fipc_send.

send in place
void* out;
if (fipc_send_acquire(conn, 64, &out,
                      FIPC_FOREVER) == FIPC_OK) {
    int n = snprintf(out, 64, "tick %d", tick);
    fipc_send_commit(conn, (size_t) n); /* publish n bytes */
}
receive in place
const void* data;
size_t len;
if (fipc_recv_acquire(conn, &data, &len,
                      FIPC_FOREVER) == FIPC_OK) {
    handle(data, len);       /* read-only, in the ring */
    fipc_recv_release(conn); /* frees its room */
}

RPC

fipc_rpc_msg_t, 32 bytes

An RPC message is a plain message with a 32-byte header in front: an id, a kind, your opcode, your status and the payload's length. A connection numbers its requests from 1, and either side may submit. Use a connection for RPC or for plain messages, not both.

client: call
enum { OP_UPPER = 1 };

uint64_t id;
fipc_rpc_submit(conn, OP_UPPER, "ping", 4, &id, FIPC_FOREVER);

char out[256];
fipc_rpc_msg_t reply;
if (fipc_rpc_recv(conn, out, sizeof out, &reply,
                  FIPC_FOREVER) == FIPC_OK
    && reply.kind == FIPC_RPC_RESPONSE && reply.id == id)
    printf("%d: %.*s\n", reply.status, (int) reply.len, out);
server: answer
char buf[4096];
fipc_rpc_msg_t req;
while (fipc_rpc_recv(conn, buf, sizeof buf, &req,
                     FIPC_FOREVER) == FIPC_OK) {
    if (req.kind != FIPC_RPC_REQUEST)
        continue;
    for (size_t i = 0; i < req.len; i++)
        buf[i] = (char) toupper((unsigned char) buf[i]);
    fipc_rpc_respond(conn, req.id, req.opcode, /*status*/ 0,
                     buf, req.len, FIPC_FOREVER);
}

All 18 functions

the exports, exactly
FunctionWhat it does
fipc_listenServer: claims a name and listens on it with rings of a given capacity. Doesn't wait.
fipc_acceptServer: waits for a client, sets its connection up on the calling thread and returns it. One client at a time. A call that times out keeps a client's setup for the next, so timeout 0 polls.
fipc_listener_cancelMakes every waiting and later accept return FIPC_CANCELLED, dropping a client whose setup began. Any thread.
fipc_listener_closeStops listening and frees the listener; accepted connections stay open.
fipc_connectClient: connects to the server listening on a name and sets the connection up on the calling thread, waiting for the server to listen and accept: client and server run on different threads or processes.
fipc_max_pieceThe longest message the zero-copy calls take: the capacity less 64 bytes.
fipc_cancelMakes every waiting and later call on the connection return FIPC_CANCELLED. Any thread.
fipc_closeEnds the connection (the peer gets FIPC_DISCONNECTED), unmaps its rings, frees the handle.
fipc_sendSends one message of any size, copying it in, in pieces if needed.
fipc_recvReceives one message of any size into your buffer.
fipc_send_acquireZero-copy send, step 1: reserves contiguous room in the ring.
fipc_send_commitZero-copy send, step 2: publishes the reserved bytes as one message.
fipc_recv_acquireZero-copy receive, step 1: the next message, in place and read-only.
fipc_recv_releaseZero-copy receive, step 2: frees the message's room.
fipc_rpc_submitSends a request and returns its id.
fipc_rpc_respondSends the response to a request id, with an opcode, a status and a payload.
fipc_rpc_recvReceives one request or response: the header and its payload.
fipc_result_strNames a result code, such as "FIPC_OK".

Results

fipc_result_t
ValueCodeMeaning
0FIPC_OKDone.
1FIPC_TIMEOUTThe timeout ran out; with timeout 0, there was nothing to do without waiting.
2FIPC_DISCONNECTEDThe peer closed the connection or its process ended.
3FIPC_CANCELLEDA cancel was called, and the call would have had to wait.
4FIPC_TOO_LARGEThe message doesn't fit the buffer, or one piece for zero-copy. It stays queued; its length is reported.
5FIPC_INVALIDA bad argument or handle, a call out of order, a peer of another version or user, corrupt ring content.
6FIPC_NO_MEMORYMemory or another OS resource ran out while setting a connection up.
7FIPC_ADDR_IN_USEfipc_listen: another listener holds the name.
